# Evidence and fairness

Each consequential finding needs an evidence ID plus a re-openable locator, or explicit 'missing evidence'. `artifact` means an artifact was inspected, NOT independently authenticated. `self_report` means asserted by candidate. `inference` must identify premises and alternative explanations. Forged-looking or inconsistent evidence is a conflict to investigate, not proof of fraud without corroboration.

Do not claim a file hash proves truth; it only pins bytes. Repository authorship, account identity and individual contribution can differ. A Git timestamp isn't a runtime log. A demo isn't production. Workflow configuration isn't observed behavior. Tests present isn't tests passing. Metrics changing isn't causation. Distinguish observed, claimed, inferred and contradicted.

Cross-reference conflicting dates, screenshots, versions, ownership, metric windows and manual intervention. Record them even if they lower the proposed level. Duplicate copies of the same assertion count once for corroboration. Negative evidence is a documented counterexample, not failure to find a file.

Use only job-relevant AI work and demonstrated contribution. Ignore demographic/protected traits, appearance, health, family situation, school/company prestige and unrelated personal data. Anonymize score packets; do not infer traits. The same rubric/version and evidence policy apply across candidates; never grade on a curve. Missing access is uncertainty, not a character judgment. Suggest focused interview verification rather than hiring/rejection decisions.

Citations display material label, page/line/commit/region. Retain absolute source paths privately in the run manifest; user-facing HTML must not embed absolute filesystem paths, secrets or irrelevant private text. Prefer a short relevant excerpt over entire private documents. A public link is supplementary, not a substitute for pinned reviewed content. Never fabricate quotes, logs, team adoption, experiments, calculations or source visits.
